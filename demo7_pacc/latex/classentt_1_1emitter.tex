\subsubsection*{template$<$\mbox{\hyperlink{namespaceentt_a8c24ecc5ab0055f9f2a4725c95afb29e}{typename}} \mbox{\hyperlink{namespaceentt_a8c24ecc5ab0055f9f2a4725c95afb29e}{Derived}}$>$\newline
class entt\+::emitter$<$ Derived $>$}
General purpose event emitter. 

The emitter class template follows the CRTP idiom. To create a custom emitter type, derived classes must inherit directly from the base class as\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keyword}{struct\ }\mbox{\hyperlink{namespaceentt_a8c24ecc5ab0055f9f2a4725c95afb29e}{my\_emitter}}:\ \mbox{\hyperlink{classentt_1_1emitter_af36907a2dc7cc0a6607533c67e072f92}{emitter}}<my\_emitter>\ \{}
\DoxyCodeLine{\ \ \ \ \textcolor{comment}{//\ ...}}
\DoxyCodeLine{\}}

\end{DoxyCode}


Pools for the type of events are created internally on the fly. It\textquotesingle{}s not required to specify in advance the full list of accepted types.~\newline
 Moreover, whenever an event is published, an emitter provides the listeners with a reference to itself along with a const reference to the event. Therefore listeners have an handy way to work with it without incurring in the need of capturing a reference to the emitter.
